# CV Analyzer

AI-powered CV/resume analysis app. Upload a PDF or DOCX CV, get a structured
score breakdown, ATS-compatibility check, "human touch" score, strengths &
weaknesses, a suggested rewrite for the weakest section, and an optional
match score against a pasted job description. Results are stored in MongoDB
and viewable in a history dashboard, with downloadable PDF/text reports.

## Setup

### 1. Prerequisites
- Python 3.10+
- A running MongoDB instance (local `mongodb://localhost:27017` or MongoDB Atlas)
- A Gemini API key from https://aistudio.google.com/app/apikey

### 2. Install dependencies

```bash
cd backend
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
```

### 3. Configure environment

```bash
cp .env.example .env
# then edit .env and set at least:
#   GEMINI_API_KEY=your_real_key
#   MONGO_URI=mongodb://localhost:27017   (or your Atlas connection string)
```

### 4. Run

```bash
python run.py
```

Then open **http://localhost:8000** — the FastAPI app serves the frontend
directly, so there's nothing extra to run for the UI.

API docs (auto-generated by FastAPI) are available at
**http://localhost:8000/docs**.

## API summary

| Method | Path                              | Purpose                                   |
|--------|------------------------------------|--------------------------------------------|
| POST   | `/api/analyze`                     | Upload file + session_id (+ optional job_description) → runs analysis, stores it, returns full result |
| GET    | `/api/analysis/{id}`               | Fetch one stored analysis                 |
| DELETE | `/api/analysis/{id}?session_id=`   | Delete an analysis (only if it belongs to that session) |
| GET    | `/api/analysis/{id}/report?format=pdf\|txt` | Download a summary report        |
| GET    | `/api/history/{session_id}`        | List past analyses for a session          |
| GET    | `/api/health`                      | Health check (Mongo connectivity, model)  |

The frontend generates a random `session_id` on first load and stores it in
`localStorage`, so "history" is scoped per-browser. Swap this for real auth
/ user accounts if you need multi-device history.

## Notes on the Gemini integration

- Uses `google-generativeai`, model configurable via `GEMINI_MODEL`
  (default `gemini-1.5-flash`; set to `gemini-1.5-pro` in `.env` for higher
  quality at higher cost/latency).
- `response_mime_type="application/json"` is set in the generation config,
  and the prompt spells out the exact JSON shape expected — see
  `gemini_analyzer.py::RESPONSE_SCHEMA_DESCRIPTION`.
- Temperature defaults to `0.3` (within the requested 0.2–0.4 range) for
  more consistent scoring across similar CVs.
- Errors are handled explicitly:
  - **429 / rate limit** → caught as `google_exceptions.ResourceExhausted`,
    retried once with backoff.
  - **Safety blocks** → detected via empty `candidates` or a `SAFETY`
    finish reason, retried once, then a clear error is returned.
  - **Malformed / empty JSON** → validated with Pydantic; on failure,
    retried once, then fails gracefully with a 502 and a descriptive
    message rather than crashing.
- The Gemini API key is read only from the environment (`.env`), never
  hardcoded.

## Input validation

- File type restricted to `.pdf` / `.docx`.
- File size capped at `MAX_FILE_SIZE_MB` (default 10MB).
- Extracted text is rejected if too short or if it looks "garbled" (e.g.
  a scanned image PDF with no real embedded text) — this fails fast with
  a 422 before ever calling Gemini.

## Stretch goals (not implemented, but designed for)

- **Job description matching** — actually partially implemented already:
  pass `job_description` in the `/api/analyze` form data and the response
  includes a `job_match` object (match score, matched/missing keywords).
  The frontend renders this automatically when present.
- **Multi-CV comparison view** — would build on the existing `/api/history`
  endpoint; add a route that accepts multiple `analysis_id`s and returns
  them together, plus a frontend view that renders score columns side by
  side.
- **Shareable links** — the `/api/analysis/{id}` route is already
  unauthenticated and ID-based, so a "Share" button that just copies
  `https://yourhost/share/{id}` (a new lightweight read-only frontend
  route) would be a small addition. Consider adding an expiry or
  view-only flag if you go this route, since IDs are guessable UUIDs
  otherwise fine for casual sharing but not for sensitive data.

## Production notes

- Set `CORS_ORIGINS` to your real frontend origin(s) instead of `*`.
- Put this behind HTTPS; file uploads and CV content are sensitive.
- Consider rate-limiting `/api/analyze` per session/IP to control Gemini
  API costs.
- MongoDB documents currently store the full analysis with no TTL —
  add a retention policy / index if needed.
